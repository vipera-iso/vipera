A local model server for hardware that only just fits it.

Vipera reads a .gguf, measures the machine, and decides how many layers go to the GPU before it loads anything. Then it serves the result as an OpenAI-compatible endpoint.

  • pip install vipera-ai[llama,gguf,nvidia]
  • vipera model search
  • vipera serve start → 127.0.0.1:8686/v1
Hermes-4-14B Q3_K_M · 40 layers · 4 GB card · 8K context measured, not estimated
17 / 40layers on the GPU
3.37 GBof 3.64 GB VRAM
6.57 t/sdecode, 64 tokens generated
0.2 t/sthe same model, CPU only

Why the answer is 17, and not zero

A 14B model at Q3 does not fit in 4 GB, so the safe answer is “CPU only” — and 0.2 tokens/second is technically an answer. Layers are independent, though. Seventeen of them fit beside the CUDA context at 8K, and the rest run from system RAM.

Vipera prices each layer before it loads: the mean weight size, plus that layer's slice of the KV cache, against the VRAM left after a reserve it calibrated by measurement. If the context cannot be created, it walks the split down (17 → 16 → 15 → 7) instead of dropping to CPU, and prints what it changed at each step.

plan 17/40 layers q8_0 KV flash attention on 3.37 GB / 3.64 GB
load context 8192 created in 2.7 s
serve 127.0.0.1:8686/v1 6.57 tok/s

What you get for installing it

A plan you can read
Every flag comes from the hardware probe and the model metadata, and every number in the planner has the measurement that produced it in a comment beside it.
A fallback that reports itself
A failed load degrades stage by stage and says which stage failed, instead of crashing or quietly serving from the CPU.
One engine behind both surfaces
vipera chat, vipera bench and /v1/chat/completions share the same loaded model, so a benchmark describes the server you actually run.

Install

The distribution is vipera-ai. The PyPI project named vipera is an unrelated PDF tool, so install the one with the hyphen. llama-cpp-python builds against your platform, which is the slow part.

pip install "vipera-ai[llama,gguf,nvidia]"
vipera model search # pick a GGUF from Hugging Face
vipera serve start # http://127.0.0.1:8686/v1

Bare metal, containers, CPU-only and Apple Silicon: install.md. Every flag: cli.md. Schemas and SSE framing: http-api.md.

What it does not do

  • No multi-model routing. One model per process, loopback by default.
  • No auth, TLS termination, or usage accounting. Put it behind a proxy that has them.
  • No web dashboard. The terminal is the interface, and it is meant to stay that way.
  • No promises about peak throughput on hardware you have already tuned — use llama.cpp/server there.
